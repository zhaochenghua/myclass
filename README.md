# MyClass 教师投屏平台

MyClass 是一套面向局域网课堂展示的投屏系统。教师电脑打开网页端，教师手机安装 Android App、或 iPhone 直接用 Safari 打开网页版，输入网页端显示的 4 位连接码，即可把手机摄像头画面通过 WebRTC 低延迟投到教室大屏。

当前版本重点支持“手机摄像头拍摄试卷、讲义、实验器材并投到大屏讲解”的场景。iPhone 用户无需安装 App，把网页版“添加到主屏幕”即可像原生应用一样使用。

## 主要功能

- Android 手机摄像头直播到网页教师端。
- iPhone / iPad 通过浏览器网页版直播到网页教师端（无需上架 App Store）。
- 支持前置/后置摄像头切换。
- 支持 1080p 级别高清采集，尽量保持摄像头原始比例。
- 支持后置摄像头补光灯。
- 支持双指缩放、点击对焦。
- 支持锁定画面，方便针对某一帧详细讲解。
- 锁定帧支持双指放大、单指拖动画面平移，手机端和网页端同步生效。
- 横竖屏自适应：竖屏保持摄像头原始比例，横屏网页端全屏裁切显示。
- App 进入后台后恢复前台会重新连接教师端并恢复直播。
- 网络不佳时优先显示最新帧，避免积压旧帧导致页面卡死。
- 网页端支持画笔标注，可用手指、触控笔、教鞭或鼠标圈画。
- 网页端画笔支持撤销和清空。
- 标注绑定到视频内容坐标；手机端移动锁定画面时，网页端标注会跟随画面移动，避免错位。
- iPhone 网页版支持“添加到主屏幕”全屏运行、离线打开界面、课件上传与播放。
- PPTX 演讲者备注随课件提取：Android / iPhone / iPad 播放时点“演讲”打开演讲者视图，可看当前页 / 下一页、备注、计时与页码进度，磨课时可当场修改（不投大屏）。
- 管理后台“任教班级”支持按次登记作业（优秀 / 涉抄 / 错多 / 未交，可自定义改名、增删与配色）并查看历次统计、导出 CSV。
- 手机端服务器课件列表使用 4:3 缩略图，网页与链接也有独立占位缩略图；横屏双列时按固定行高排布，长文件名最多两行并自动省略，不会把相邻课件挤乱。

Android App 支持手机屏幕共享（整块屏幕或单个应用），开始后自动退到后台，教师直接切换到要展示的内容；
iPhone 网页版受 iOS 限制不提供屏幕共享。

## Android 电视大屏接收端

独立电视模块位于 `android/AndroidStudioProject/tv/`，最低支持 Android 5.0，默认使用
`https://sz.imst.xyz/myclass/`。提供原生 WebRTC 接收、课件与图片显示、视频播放和遥控器操作，
与手机发送端可共存。构建、安装、兼容限制及模拟器验证见 [电视端说明](android/AndroidStudioProject/tv/README.md)。

## Windows 电脑投屏客户端

Windows 端客户端位于 `windows/`，使用 Electron 将指定显示器或单个应用窗口的画面和 Windows 系统输出声音通过现有 WebRTC 链路投到教室大屏。它复用当前连接码和 `/myclass/ws` 信令，不需要新增媒体中转服务；关闭窗口后程序继续驻留系统托盘。客户端设置中可以选择投屏时是否同时在笔记本上播放声音。

开发、打包和系统声音兼容性说明见 [`windows/README.md`](windows/README.md)。快速启动：

```powershell
cd windows
npm install
npm start
```

`web/public/myclass.apk` 是 Android 构建后的分发产物，默认不提交到 Git。Windows 安装包发布为 `web/public/myclass-windows.exe`，服务端页面会显示对应的下载链接。

## 服务端部署

默认访问地址：

```text
http://10.30.13.1/myclass/
```

安装 Node.js 20 或更高版本，然后执行：

```bash
cd server
npm install
npm start
```

默认服务监听 `0.0.0.0:3000`，页面路径是 `/myclass/`。如果服务端要直接使用 80 端口：

```bash
PORT=80 npm start
```

也可以放在 Nginx 后面反向代理到 Node 的 3000 端口，但需要同时代理 WebSocket：

```nginx
location /myclass/ {
    proxy_pass http://127.0.0.1:3000/myclass/;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
}
```

常用环境变量：

```text
SERVER_IP=10.30.13.1
HOST=0.0.0.0
PORT=3000
PATH_PREFIX=/myclass
PUBLIC_BASE_URL=http://10.30.13.1/myclass
ALLOWED_HOSTS=10.30.13.1,localhost,127.0.0.1,ai.nbsdszx.cn,sz.imst.xyz
ROOM_TTL_MS=7200000
APP_VERSION=1.1.28-20260622
HTTPS_PORT=443
TLS_KEY=server/data/tls/server.key
TLS_CERT=server/data/tls/server.crt
IOS_BASE_URL=https://10.30.13.1/myclass
IOS_VERSION=1.0.0
LIBREOFFICE_PATH=C:\Program Files\LibreOffice\program\soffice.exe
COURSEWARE_MAX_BYTES=2147483648
COURSEWARE_REQUEST_TIMEOUT_MS=1800000
COURSEWARE_CONVERT_TIMEOUT_MS=120000
COURSEWARE_LIST_LIMIT=0
FONT_SCAN_LIMIT=10
FONT_REGENERATE_LIMIT=10
```

“播放课件”功能由手机 App 选择本机 PDF/PPT/PPTX 并上传到服务端。PDF 会直接发布，PPT/PPTX 会通过 LibreOffice headless 转换为 PDF 后在网页端自动打开，并写入服务器暂存课件列表；App 后续可直接选择或删除服务器课件，避免大课件重复上传。网页端使用本地 PDF.js 单页渲染课件；横向幻灯片整页显示，竖向 A4 文档按屏幕宽度铺满并支持上一屏/下一屏、长按快速定位页码与手型拖拽。画笔标注绑定在课件页坐标上，会跟随拖动画面移动。服务器需要安装 LibreOffice；如果不在默认路径，请设置 `LIBREOFFICE_PATH` 或 `SOFFICE_PATH`。

PPT/PPTX 新上传时默认通过 ExpandAnimations 将“出现/消失”动画按点击展开成多个静态 PDF 页，网页及手机沿用原有翻页控制。无需 Windows 或 Microsoft Office。设置 `PPT_ANIMATION_MODE=static` 可恢复普通静态转换；旧课件需要重新上传才会展开。支持范围、Linux 实测对比、部署和回滚方式见 [PPT 动画展开说明](docs/ppt-animation-expansion.md)。

大屏翻页在后台画布绘制完整后一次替换显示，等待期间保留上一屏及其笔迹，避免动画拆页切换时闪白。后台优先预渲染下一屏，再准备上一屏；像素缓存最多三张、合计不超过 64 MiB，换课件或显示尺寸变化时失效。无需重新上传课件。浏览器回归：`node scripts/test-courseware-rendering.cjs`（需 Playwright，默认使用 Edge）。

HTTP 和 WebSocket 会检查 `Host` 与 `Origin`，默认允许 `10.30.13.1`、`localhost`、`127.0.0.1`、`ai.nbsdszx.cn` 和 `sz.imst.xyz`。可通过 `https://sz.imst.xyz/myclass/` 访问域名反向代理入口；若设置了 `ALLOWED_HOSTS`，该变量会覆盖默认名单，需同时包含上述域名。

### 任教班级与随机抽学生

教师登录管理后台后，进入“任教班级”，添加班级并录入名单。每行填写“学号 姓名”，可直接粘贴 Excel 的两列（支持“学号、姓名”表头）；支持班级改名、学生增删改和删除班级。学生名单设置默认折叠，点“学生名单设置”展开，空班级会自动展开；保存班级与名单、删除班级按钮始终可见。学号按文本保存、保留前导 0，同班学号不能重复；每班最多 500 人，每位教师最多 100 个班级。同名学生允许存在，抽姓名时同时显示学号以便区分。

教师直接在大屏登录，或从已登录的手机连接课堂后，大屏会加载该教师的班级。有班级时可选择一个班级，也可“不选择班级”。投屏、课件、图片、视频或电子黑板上课过程中，可按姓名或实际学号抽取；没有班级或不选择班级时，继续使用原来的 1–80 人设置及按人数抽学号流程。选中的空班级会提示先录入名单，不会悄悄改为随机学号。每次名单抽取都重新读取班级，避免使用已经删除的学生。

安卓的“抽学生”按钮放在摄像头、课件、图片、视频及共享屏幕的上课界面，功能菜单不放抽取按钮。新版手机输入连接码后，有任教班级时可直接选择班级和姓名/学号；不选班级可在手机设置抽取人数。功能菜单的“班级/抽取设置”可重新选择，上课中长按“抽学生”也能修改。设置须由大屏确认后生效，双方修改会同步，刷新大屏后手机会恢复已确认设置。手机触发大屏抽取并接收同一个结果，抽取不关闭投屏。连续点击会提示等待，连接异常时提示重试，不会自动补发导致重复抽取。旧版手机仍可连接新版大屏，并沿用大屏选择班级的方式。

安卓启动时先检测校园服务器 `/health`，不可达时显示校园网络提示及“打开 Wi-Fi 设置”“重新检测”，不展示误导性的账号密码表单。区分无网络、非 Wi-Fi 和 Wi-Fi 下服务器不可达；不读取 SSID、不索取定位权限，校园 Wi-Fi 无公网验证也不因此拒绝连接。网络恢复后重试并保留原登录凭据，只有认证返回 401 才清除过期登录。

班级数据保存在 `server/data/classes.json`，API 为登录后的 `/api/classes`。每个教师只能读写自己的班级，管理员账号也按本人名单隔离。索引原子写入，编辑、删除校验 `revision` 防止多个页面互相覆盖；删教师时一起清理其名单。部署更新 Node 服务和网页后需重启服务并刷新浏览器；APK 和 `server/data/versions.json` 可保持原版本，等模拟器验证及人工验收后再发布手机更新。

抽取进度跨课次保留：选定班级时按教师、班级保存到服务器 `classes.json`，刷新大屏、重新登录、换教室或重启服务后继续本轮，全班抽完才开始下一轮；多个大屏同时抽取也共用进度。新一轮优先避开最近半个班人数内抽到的学生。班级改名、学生改名、切换姓名/学号不重置进度，新增学生加入当前轮，删除学生不再参与。按人数抽学号时，进度按教师保存在当前浏览器（未登录时使用该浏览器的公共进度）；不同班级需选择各自名单才能区分，清除浏览器数据会清空这类本地进度。

#### 课件播放进度按班级保存

课件播放进度不再全学年统一：选定班级上课时，手机课件列表里的“上次第 x / y 页”、进度条和“继续播放”提示只使用该班自己的进度；不选择班级时继续使用原来的通用进度。大屏实际显示到哪一页就保存到当前确认的班级，换班上课不会互相覆盖，同一课件可以在不同班级各自续播。

进度按教师和班级记录在课件索引 `index.json` 中，班级改名、编辑名单不会丢失；删除班级会一并清理该班的课件进度。手机列表会在顶部显示“当前班级：…”，续播提示也会带上班名，避免把两个班看串。接口为登录后的 `GET /api/courseware?classId=<班级 id>`，不传 `classId` 时返回未选班级的通用进度；Android 与 iPhone 网页版使用同一份数据。

课件管理页（Android“用户管理 → 课件管理”、iPhone 网页版“课件管理”）也可以单独选择“查看班级”，只改变管理页显示的进度，不会影响正在上课的班级。班级选择在播放列表上方独立成行，横屏、竖屏和窄屏下都不会挤压标题栏；Android 横屏的上传/返回按钮统一宽度，避免返回按钮比同排按钮小。

在“任教班级”选中班级后，下方“已抽学生记录”会列出上课时抽中的学生、时间、轮次和抽取方式（姓名/学号），方便老师课后回顾课堂提问情况。记录由大屏或手机在课堂上抽取时自动写入服务器，最多保留最近 500 条；可手动刷新或清空，清空记录不会重置抽取进度。记录接口为登录后的 `GET/DELETE /api/classes/:id/draw-log`，其他教师无法读取。

#### 作业登记与统计

“任教班级”选中班级后，可在“作业登记”中填写日期和作业名称新建一次作业；名称留空会自动命名为“10 月 28 日作业”。随后直接在每位学生姓名后点“优秀 / 涉抄 / 错多 / 未交”即可登记该次作业，再点一次同一状态可取消。连续点选会合并为一次保存，刷新页面、重新登录或换设备后仍保留。若当前选中的不是今天的作业，页面会提示先新建，避免把今天的新作业登记到旧记录上。

默认提供“优秀 / 涉抄 / 错多 / 未交”四个按钮。点“状态设置”可以按班级修改按钮名称、颜色，或增删按钮（最多同时启用 8 个，至少保留 1 个）。改名会同步历史记录；已经用过的状态删除时会转为停用，不再显示登记按钮，但历史统计与 CSV 仍保留该列，也可以随时恢复；未使用过的状态才会真正删除。状态设置只影响当前班级。

“历次作业统计”按作业日期汇总各状态人数，并按学生列出历次记录、个人合计和“未登记”数，可导出 CSV（带 BOM，Excel 可直接打开）。未点选任何状态计为未登记；名单中删除的学生不计入统计，同一学号重新加入后恢复显示历史记录。每班最多保留 200 次作业记录，可删除单次记录；删除班级会一并删除作业记录。数据仍保存在 `server/data/classes.json`，接口为登录后的 `GET/POST /api/classes/:id/homework`、`GET/PATCH/DELETE /api/classes/:id/homework/:homeworkId`、`GET /api/classes/:id/homework/stats`，以及状态设置使用的 `GET/POST /api/classes/:id/homework-statuses`、`PUT/DELETE /api/classes/:id/homework-statuses/:statusId`，部署时无需迁移。

开发验证：`cd server && npm test`，或运行 `node server/testSupport.js` 启动仅含虚构测试账号的隔离环境（端口 3107）。作业登记的浏览器完整流程可运行 `node scripts/test-admin-homework.cjs`，自定义状态按钮可运行 `node scripts/test-admin-homework-statuses.cjs`（均需 Playwright 与 Edge）。模拟器可用 `adb reverse tcp:3107 tcp:3107` 配合 `-PMYCLASS_SERVER_URL=http://127.0.0.1:3107/myclass` 增量安装，不修改正式地址或安全白名单。备份班级数据时应包含整个 `server/data`。

### 服务器字体与缺少字体提示

“字体管理”支持教师上传 TTF/OTF/TTC 并搜索已安装字体，字体安装后对后续所有课件转换生效。上传 `.pptx`/`.docx` 时服务器会读取文档引用的字体并与服务器字体比对；缺少字体时页面顶部和标签页会提示，并只列出**当前账号上传的**受影响课件。按提示上传字体后，系统自动重新生成当前账号的这些课件（保持课件 ID、链接、播放进度和手写笔记不变），无需重新上传课件。旧课件会在打开字体页时分批补扫；`.ppt`/`.doc` 二进制格式暂不检查字体。非 Linux 环境不显示该提示。安装要求、接口和验证方式见 [服务器字体管理](docs/server-fonts.md)。

### 大屏触屏校准

“触屏校准”按钮仅在连接码首页显示，投屏、课件、视频和电子黑板中自动隐藏，已保存的校准仍然生效。建议先进入全屏；有任教班级时先选择当前班级，再点“开始 / 重新校准”，用上课时的触控笔或手指依次轻点五个十字中心。完成后在空白处试写，确认笔迹跟随触点再点“保存校准”；误点、拖动或偏差异常会提示重试。关闭未保存的校准不会替换原数据，“恢复默认”可清除当前校准。

选择班级后，校准随该班级存入服务器 `server/data/classes.json`，以后在大屏或手机选择同一班级时自动加载，班级改名、编辑名单不会丢失校准。未选班级时仅保存在当前浏览器；本地数据不会自动覆盖班级数据。不同教师的班级沿用现有权限隔离，不能读取或改写他人的校准。多块大屏同时保存同一班级时会检查校准版本，提示重新加载，避免互相覆盖。

校准修正大屏本地画笔、直线、板擦、圈选及拖动/缩放坐标，同时修正投屏和电子黑板工具条（含弹出菜单）的按钮命中位置，也适用于把触摸模拟为鼠标的红外触摸框；手机传来的笔迹不重复修正。两种工具条的画笔默认使用深红色。校准适用于当前显示尺寸和全屏状态，分辨率、浏览器缩放或全屏状态变化后暂停使用，恢复原状态会自动重新启用；换教室、调整投影范围后应重新校准。此功能修正偏移、缩放及轻度倾斜误差，不能替代投影仪或系统触摸驱动的硬件校准。

大屏画笔和板擦采用单指书写、双指缩放，适用于课件、图片、直播、电脑投屏和电子黑板。为减少红外屏的大拇指、灰尘误触，第二指须在落笔 300 毫秒内、累计书写距离不超过 40 CSS 像素时落下，初始间距至少 64 CSS 像素；随后 400 毫秒内，两指沿连线反向各移动至少 8 像素且间距变化至少 24 像素后才确认缩放。确认前显示临时笔画并暂缓回传，确认缩放后丢弃该笔画并从当前位置开始缩放，不留下短线或擦除痕迹；确定为正常书写或抬指时补齐同步笔迹。书写中途、贴近或静止的额外触点不触发缩放。缩放后须抬起全部手指再落指恢复书写；不支持大屏本地多点同时书写。手型工具仍支持单指拖动与双指缩放，手机笔迹继续独立同步。验证：`node scripts/test-handwriting-pinch.cjs`。

- **手掌触屏 = 临时橡皮擦**：手写笔正在写（或手掌接触面明显大于手指）时落下的手掌触点不再画线，而是当橡皮擦使用；抬手后自动恢复为画笔，不改变当前工具选择。手掌橡皮擦与手写笔可以同时存在，不会挡住正在写的笔画。
- **方块板擦**：板擦的落点光标与擦除范围都改成方块（不再是圆形），更接近实体板擦。
- **换色回到实线**：切换画笔颜色后线型自动回到默认实线，避免把上一节课留下的虚线/点划线带进新课。
- **点划线更像工程制图**：虚线、点划线改用平头笔帽并拉长划与间隙（点划线为长划—间隙—点—间隙），远看不再糊成实线。

部署验证可设置 `MYCLASS_TEST_BASE_URL=http://10.30.13.1/myclass` 后运行 `scripts/test-handwriting-pinch.cjs` 和 `scripts/test-pdf-compatibility.cjs`，直接加载线上页面及 PDF 组件；测试课件通过浏览器拦截提供，无需登录或上传文件。

验证：`cd server && npm test`；浏览器完整流程：安装 Playwright 后运行 `node scripts/test-touch-calibration.cjs`（默认使用 Edge，也可通过 `BROWSER_PATH` 指定 Chromium）。自动测试使用隔离数据和虚构账号，截图保存在系统临时目录 `myclass-calibration-proof`。

### 课件存储与备份

默认目录仍为 `web/public/courseware`，原有课件的 ID、URL、教师归属保持兼容。可通过环境变量 `COURSEWARE_ROOT` 指定独立数据盘上的绝对路径，下载仍使用 `/myclass/public/courseware/<id>.<扩展名>`，无需修改手机端。

- 新上传文件按 SHA-256 和扩展名去重，内容池放在课件目录的 `.objects/<哈希前两位>/<哈希及扩展名>/`。每条记录仍有独立 ID、标题、所属教师和公开文件路径；支持硬链接的磁盘上，这些路径共用内容数据，不额外复制大文件。重复 Office 文件复用已生成的 PDF。格式或内容不同的文件分别保存。
- 保留图片、视频、Office 原文件，不做有损压缩。文件仍需完整上传后才能计算哈希，本功能节省磁盘及重复转换时间，不属于客户端“秒传”。不支持硬链接的文件系统会退回复制，磁盘去重效果相应失效。
- 上传、改名、删除串行更新索引，索引写入临时文件并原子替换；不再按 100 条截断记录。`COURSEWARE_LIST_LIMIT=0` 表示返回全部可见课件，正数只限制列表返回量，不删除任何记录；旧的 `COURSEWARE_INDEX_LIMIT` 不再使用。损坏或空白索引会报错，须从备份修复，不会覆盖为空列表。
- 删除课件会移除该记录关联的图片、视频、PDF 和 Office 文件；共享内容在最后一条引用删除后才回收。上传或转换失败会清理本次新建的文件。若进程被强制终止，可能留下暂存文件或无索引文件，不自动猜测其归属或批量删除。
- 升级不自动迁移、压缩或清理已有文件，存量重复文件不会立即节省空间。已有索引之外的旧文件不再自动作为“所有人可见”的课件展示；应从备份核对归属后恢复记录。仅完全没有索引的旧安装会在首次读取时导入原有 PDF。

当前设计用于一个 Node 服务进程，Office 转换按上传提交顺序执行，读取列表和已发布文件不必等待转换。不要用多个进程同时写同一课件目录；如需集群，应先迁移到支持事务和跨进程协调的存储。

备份需覆盖整个课件目录（包括 `index.json` 和隐藏的 `.objects`、`.annotations`、`.notes`），以及 `server/data` 中的用户数据。建议停服后备份或使用文件系统快照，Linux 复制目录使用保留硬链接的工具选项（如 `rsync -aH`）。公开文件和内容池通过硬链接关联，不要原地编辑已发布文件；更新课件应重新上传。

切换到 `COURSEWARE_ROOT` 前，应停服、备份并完整复制旧课件目录，确认文件与索引齐全后再设置新路径和启动服务。反向代理应把整个 `/myclass/` 转发给 Node；若 OpenResty 直接托管课件文件，必须额外禁止访问 `index.json`、隐藏目录和临时文件。Node 已限制这些路径的访问，并保留下载及视频 HTTP Range 支持。

上线需同时更新 `server/server.js` 和 `server/coursewareStore.js`，然后重启 Node 服务，无须重新打包 APK 或 EXE。回滚前备份最新课件目录；原有公开文件路径仍兼容旧代码，但旧代码不具备去重回收和索引保护能力。

HTTPS 与 HTTP 由同一个 `RoomManager` 管理，因此大屏端走 http、iPhone 走 https 时连接码依然匹配，两种协议可以混用。

## iPhone 网页版（iOS）

iOS 浏览器无法实现屏幕共享，且上架 App Store 成本较高，所以 iPhone / iPad 直接提供网页版：
用 Safari 打开 `https://10.30.13.1/myclass/ios/`，点底部分享按钮 → “添加到主屏幕”，
桌面会生成图标，之后点开即全屏运行，没有地址栏，体验与原生 App 一致。

### 为什么必须用 https

iOS Safari 只在**安全上下文**中开放摄像头，在 `http://10.30.13.1/...` 下调用 `getUserMedia` 会直接失败。
因此服务端需要额外监听一个 HTTPS 端口；教室大屏仍可继续使用原来的 http 地址，两者共用同一套连接码。

### 部署步骤

**方式一（推荐，已有 Nginx/OpenResty 反代）：** 本项目部署在 1Panel OpenResty 后，
`proxy/myclass.conf` 已把 `/myclass/` 反代到 Node 的 3000 端口（含 WebSocket 头），
443 上已有 TLS。此时 **Node 不需要监听 HTTPS**，直接用现成入口：

1. 确认 `server/data/versions.json` 里有 `iosVersion` 字段（没有则补上）。
2. 用新版代码重启 Node 服务（改代码后需重启）：

```bash
cd server
# 停掉旧进程后：
nohup node server.js > /home/zch/myclass-server.log 2>&1 &
```

   服务端 `IOS_BASE_URL` 默认回退为 `https://<SERVER_IP>/myclass`，反代可达，无需额外配置。
   若想用已有 https 域名，可设 `IOS_BASE_URL=https://ai.nbsdszx.cn/myclass`。

3. 教室大屏页面点“iPhone 网页版”按钮，会弹出二维码和使用说明。
4. iPhone 扫码后用 Safari 打开 `https://10.30.13.1/myclass/ios/`，
   出现“此网站的安全证书无效”时点“显示详细信息” → “访问此网站”。
   首次开启摄像头时同样允许一次即可。

**方式二（无反代环境）：** 让 Node 自己监听 HTTPS。

1. 生成自签证书（证书必须带 IP SAN，否则 iOS 校验不通过）：

```bash
SERVER_IP=10.30.13.1 bash scripts/generate-selfsigned-cert.sh
```

   需要域名也能访问时追加 `EXTRA_DNS=ai.nbsdszx.cn`。证书生成在 `server/data/tls/`，已被 `.gitignore` 忽略。

2. 带 HTTPS 端口启动（443 需要 root 权限，普通用户可改用 8443 并设置 `IOS_BASE_URL` 带端口）：

```bash
cd server
HTTPS_PORT=443 PORT=3000 npm start
```

> 如果服务器已有正式证书（例如通过域名 https 访问），直接把 `IOS_BASE_URL` 指向该域名即可，
> 不需要自签证书，也不用设 `HTTPS_PORT`。

### 实现要点

- 画面统一先绘制到 canvas，再用 `canvas.captureStream()` 推给 WebRTC。
  这样在不依赖任何原生能力的前提下也能实现数字变焦、锁定帧和静态图片推流。
- 锁定画面时停止重绘 canvas，并定时调用 `track.requestFrame()`，保证大屏端画面不中断。
- `teacher.orientation` 上报的裁剪区域采用“已旋转后的显示画面坐标”，
  因此大屏端画笔标注同样会跟随手机端的缩放和平移。
- **iPad / iPhone 端标注**（`web/ios/js/annotation.js`）与 Android 端 `AnnotationStroke.kt` +
  `ZoomableImageView.kt` 完全同构：
  - 归一化坐标以“内容显示矩形的 AABB”为基准——图片是 `<img>` 经旋转/缩放/平移后的外接矩形，
    课件是页面画布的显示矩形，与大屏端 `currentVideoContentRect()` 口径一致，因此两端笔迹位置重合。
  - 一笔走 `courseware.annotation` 的 `begin → points（60ms / 12 点节流）→ end`，
    `undo / clear` 按页生效（图片投屏 `page = 0`，课件投屏传当前页码）；
    大屏端画笔通过 `viewer.annotation` 回传，本地同样回放，两端笔迹栈保持一致。
  - 板擦走 `destination-out`，只擦笔迹不擦底图；画笔 4 CSS px、板擦 40 CSS px，与大屏端同一单位。
- 课件页用与大屏端同一份 pdf.js（`/myclass/vendor/pdfjs`）渲染成位图，
  从而复用与图片投屏完全相同的标注能力；课件按页缓存笔迹，翻页自动存取。
- **课件预览的缩放 / 平移 / 逐屏**（`web/ios/js/app.js` 中的“课件预览视口”一节）
  与安卓端 `ZoomableImageView`（FitWidth）逐项对齐：
  - 页面默认按「宽度充满舞台」显示（同 FitWidth），长页直接在舞台上上下拖动查看；
    上一页 / 下一页先在页内逐屏滚动（留 8% 重叠），滚到边界才真正翻页。
  - 例外：**横向课件**（宽高比 ≥ 1.2，即 4:3 / 16:9 这类幻灯片页）在横屏舞台上按宽度
    铺满会被裁掉底部——手机横屏的舞台比课件更扁（宽高比 1.8~2.2 vs 16:9 的 1.78），
    裁掉几个像素就会让「一屏放不下」成立，同一张课件要点两次才翻页。因此这类课件改为
    收窄到「整页刚好放得下」（`applyCoursewareFit`，手机横屏无条件收窄，平板只在宽度
    损失 ≤3% 时收窄）；竖向长课件（A4 试卷等）仍按宽度铺满 + 逐屏滚动。
  - iPad 整页能显示完、但按 16:9 估算大屏是长页时，走「大屏滚动模式」
    （`bigProgressY`）驱动大屏逐屏下滚，避免 iPad 直接翻页导致大屏不滚动。
  - iPad 上的每一次缩放 / 平移都会同步大屏：`courseware.image.viewport` 走
    `progress=true` + `page`（滚动进度归一化 + 分页），两端屏幕比例不同也能保持一致。
  - **播放中临时切出 / 回来**：播放页左上「菜单」= 回菜单但课件继续留在大屏（本地预览也不
    释放），用于上课途中临时投摄像头 / 图片；功能菜单里的「继续播放课件」（仅播放中显示）
    按当前页把课件重新推给大屏并回到播放页。「结束播放」才是真的结束并释放。
    走图片 / 视频投屏时课件改为"挂起"（`suspendCourseware`，保留 `state.courseware` 与页码，
    并忽略投屏期间大屏回传的页码——大屏端图片/视频也走课件通道），所以摄像头、图片、视频
    三种临时投屏之后都能继续播放原课件；「继续播放课件」会顺手清掉本地投屏队列。
  - **播放页状态栏只显示页码**（`第 x / y 页`）：原来的「第 x / y 屏」「1.5x」是按缩放和滚动
    折算出来的，一次捏合就变，会把底部横条挤到第二行（实测 iPad mini / 10.9" 因此整屏上下
    跳），故去掉；放大倍数在画面上可见，屏数信息不再需要。
  - 画笔模式下单指绘制、双指缩放平移（第二指落下自动结束当前笔画），缩放最大 8x 与安卓一致；
    向前翻页落在上一页底部，便于向上逐屏回顾。
    **与安卓不同的一处**：iOS 端取消了「双击 2.5x 放大」——双击放大与下面「点动翻页」争的是
    同一个双击判定窗口，保留它就得让每次点动翻页都等 ~340ms，实测明显发懒。要放大用双指捏合。
  - **翻页的外接入口**：安卓端的「音量键翻页」在网页端做不到——iOS 的音量键由系统独占，
    不派发任何 `keydown`（安卓网页同样收不到，安卓端能用是因为原生 App 在
    `dispatchKeyEvent` 里拦截）。网页端改为支持蓝牙翻页笔 / 外接键盘的
    `PageUp` / `PageDown`（也接受方向键），见 `handleCoursewarePagingKey`：
    只在课件播放页生效，输入页码框里自动让行；万一浏览器派发音量键事件，
    也按安卓规则（音量+ 上一页、音量- 下一页）处理。
  - **点动翻页**（`bindCoursewareGestures` 里的 `paging`）：点画面左半边上一页、右半边下一页。
    非画笔模式单指即可（多一根手指也认），画笔模式单指留给写字、得用双指。
    **抬手立即翻页**，不留任何判定延迟；移动超过 `CW_TAP_MOVE_SLOP_PX`(12px)
    或按住超过 `CW_TAP_MAX_DURATION_MS`(500ms) 都不算点动（手指搭在屏幕上、擦屏幕不翻页）。
    连点两下就是翻两页（双击放大已取消，不会吞掉第二次点击）。
  - **滑动翻页**：横向位移 ≥ `CW_SWIPE_MIN_DISTANCE_PX`(60px) 且大于纵向
    `CW_SWIPE_AXIS_RATIO`(1.5) 倍，左滑下一页、右滑上一页；只在未放大时生效
    （放大后横向拖动是平移）。它与点动互斥——点动要求"几乎没动"，一次触摸只会命中一种，
    所以两种可以同时保留。手势中途加减手指（比如抬掉双指中的一根）一律不翻页。
    两种手势的翻页动作都与按钮 / 翻页笔一致，走 `navigateCourseware`
    （长页先逐屏滚动、到边界才真正翻页）。
  - **两指手势分开判定**：两指落下后，先看"间距变化"还是"中心移动"先超过各自的阈值
    （`CW_PINCH_SLOP_PX` 20px / `CW_PAN_SLOP_PX` 12px），认定成捏合或平移后这一轮不再改：
    平移的那一轮不缩放（双指滑动时手指间距的自然漂移不会把画面放大），捏合的那一轮不翻页。
    平移分量始终生效，所以"捏合的同时拖动"仍然可用。
  - **收起键盘后的视口复位**：iOS 会为聚焦的输入框偏移可视视口，而用键盘上的"完成"收起键盘时
    **输入框仍然持有 focus**。旧实现只看 focus，于是永远以为"还在输入"、偏移一直不复位，
    画面看着正常但点击整体落到别处（表现为"所有按钮都失效"，页码输入框最容易碰到）。
    现按可视视口高度判断键盘是否真的还在（`keyboardVisible`，容差 40px），键盘不在了就
    `resetViewportOffset()`（连 `documentElement` / `body` 的滚动一起归零，且不再用
    "scrollY 非 0 才复位"的判断），并在 `resize` / `focusout` / 回到前台后再补 80ms、320ms
    两次（收起键盘是异步的）；每次 `pointerdown` 之前也确认一次。键盘确实弹着且正在输入时
    仍然让位，不把输入框推到键盘后面。

### 横屏适配

iPhone 网页版的横屏策略与安卓端 `MainActivity`（`ORIENTATION_LANDSCAPE` 时重建布局）保持一致，
全部由 CSS 媒体查询实现，不依赖 JS 判断方向：

| 页面 | 竖屏 | 横屏 |
| --- | --- | --- |
| 登录 / 连接码 / 功能菜单 / 投屏来源 | `.panel` 单列 | 左右两栏（左＝标题与状态，右＝输入与按钮），对应安卓 `landscapeRoot()` |
| 图片视频投屏 | 预览在上、控制在下 | 左＝预览占满剩余空间，右＝15rem 竖栏放工具栏与标注栏，对应安卓 `dp(240)` 侧栏 |
| 课件播放 | 预览在上、控制在下 | 宽屏（iPad，≥ 60rem）：课件占满整屏，标注栏与翻页控件收进屏幕底部横条；手机（横屏高 ≤ 30rem）：取消顶部标题栏那一行，课件独占整屏高度，右侧 8rem 窄竖栏（菜单/画笔/标注/翻页都在竖栏里） |
| 服务器课件列表 | 单列列表 + 底部按钮 | 列表双列占左侧，上传按钮收进右侧竖栏 |
| 摄像头直播 | 工具栏在底部 | 工具栏移到右侧竖栏（宽 5.6rem），对应安卓 `dp(86)` 侧栏 |

实现要点：

- `.panel-side` / `.panel-main` 在**竖屏用 `display: contents`**，子元素直接参与 `.panel` 的单列布局，
  再用 `order`（标题 0 / 表单 1 / 底部说明 2）还原成改造前的顺序，因此竖屏观感完全不变；
  横屏时才变成真正的两栏。
- `.view` 的左右内边距同样叠加 `env(safe-area-inset-left/right)`，横屏刘海/灵动岛机型不会被遮挡。
- 横屏给具体视图用了 `display: grid`（ID 选择器），因此 `.view[hidden]` 必须 `!important`，
  否则隐藏会失效——后续新增类似规则时注意这一点。
- 矮横屏（`max-height: 30rem`，即 iPhone 横过来）再压缩字号与内边距，保证一屏放得下。
- 旋转会触发 `resize`，标注画布会重新按新的内容显示矩形重绘，笔迹不会错位。
- 信令消息、课件接口、连接码规则与 Android 端完全一致，同一个连接码既能连 Android 手机，也能连 iPhone。
- 摄像头采集与推流参数固定为 1280×960 @24fps、6 Mbps（原先功能菜单里的「画质」选项
  只改这几个值，课堂投屏下看不出差别，已删除）。

## WebRTC 与信令

视频数据路径：

```text
Android App 摄像头 -> WebRTC PeerConnection -> 浏览器 video
```

WebSocket 只做信令和状态同步，不传输视频流。主要流程：

1. 教师网页连接 `/myclass/ws`，服务端生成 4 位连接码并保存到内存。
2. Android 输入连接码后发送 `teacher.join`。
3. 服务端验证连接码，成功后通知浏览器 `teacher.online`。
4. Android 点击开始直播，创建 WebRTC offer，经 WebSocket 发给浏览器。
5. 浏览器创建 answer，经 WebSocket 返回 Android。
6. 双方交换 ICE candidate 后，媒体流直接通过 WebRTC 传输。
7. Android 会通过 `teacher.orientation` 同步横竖屏、摄像头朝向、锁定帧缩放和平移裁剪区域。

局域网内通常不需要 STUN/TURN，配置中 `iceServers` 为空。后续跨网段或复杂网络环境可以在服务端配置接口中增加 ICE 服务器。

## 常见问题

### 页面打不开

确认 Node 服务已启动，并检查服务器防火墙是否允许访问对应端口。默认开发端口是 `3000`；生产环境如果要使用 `http://10.30.13.1/myclass/`，需要监听 80 端口或配置 Nginx 反向代理。

### 手机提示连接码错误

连接码只保存在服务端内存中，网页刷新会生成新连接码。请以大屏当前显示的 4 位数字为准。

### APK 二维码可以扫，但下载 404

说明 `web/public/myclass.apk` 尚未生成。先完成 Android release 构建，然后复制 APK 到 `web/public/myclass.apk`。

### 页面一直等待教师连接

确认手机和教师电脑在同一局域网或同一 OpenVPN 内网环境，并且 App 的 `SERVER_BASE_URL` 指向 `http://10.30.13.1/myclass`。

### 连接成功但没有画面

检查 Android 摄像头权限是否授权；确认浏览器支持 WebRTC；确认网络没有隔离同一局域网设备之间的 UDP 连接。

### 锁定帧放大后变模糊

锁定帧放大基于当前摄像头采集输出帧，不是基于 WebRTC 压缩后的画面，但也不是传感器完整拍照分辨率。放大倍率过高时会出现数字放大带来的模糊。若未来需要更高清的锁定放大，可增加“锁定时拍摄高分辨率静态图”的方案。

### 网页端标注为什么能跟随手机端平移

网页端笔迹保存为视频内容的归一化坐标。手机端锁定帧缩放或平移时，会把当前可见裁剪区域同步给网页端，网页端按最新裁剪区域重绘标注，因此标注会跟随画面移动。

### 是否支持手机屏幕共享

Android App 支持。功能菜单点“共享屏幕”，在系统弹窗选择“共享整个屏幕”或“共享一个应用”并确认后，
App 会自动退到后台，手机随即显示桌面或上一个应用；切换到要展示的文档、相册或网页即可。
共享期间系统通知一直保留，点通知回到控制页可停止共享。iPhone 网页版受 iOS 限制无法提供屏幕共享。

画面按手机当前方向采集，长边最高 1920（例如 1080×2400 竖屏手机输出 864×1920），
优先使用 VP8，兼顾老电视解码；电视端按原始比例显示，竖屏手机画面两侧会留黑边，这是正常的。
早期版本把竖屏手机错误地按横屏尺寸创建虚拟显示，表现为屏幕共享黑屏；1.9.9-2026102403 起已修复。
共享过程中旋转手机时，1.9.9-2026102404 会按新的整屏尺寸 resize 正在推送的虚拟显示，
并同步新的横竖屏状态；否则横屏内容会被塞进开始共享时的竖屏缓冲，大屏上只剩一个小横屏画面。

### iPhone 提示“无法访问摄像头”

iOS Safari 只在 https 下开放摄像头。请确认：

1. 访问地址以 `https://` 开头，而不是 `http://`；
2. 服务端已用 `HTTPS_PORT` 启动，或 `IOS_BASE_URL` 指向了已有的 https 域名；
3. 首次访问时在证书警告页选择了“访问此网站”；
4. Safari 的相机权限设为“允许”（设置 → Safari 浏览器 → 相机）。

### iPhone 提示证书无效

自签证书属于正常现象，点“显示详细信息” → “访问此网站”即可。
如果希望长期免提示，可在“设置 → 通用 → VPN 与设备管理”中安装并信任该描述文件，
或在“设置 → 通用 → 关于本机 → 证书信任设置”中打开对该证书的完全信任。

### iPhone 网页版没有补光灯

iOS Safari 没有开放摄像头补光灯接口，按钮会显示为“补光灯(不支持)”。
拍摄试卷时建议借助教室灯光，或用另一台手机的手电筒补光。

### 添加到主屏幕后界面打不开

主屏幕图标依赖 Service Worker 缓存，而 Service Worker 同样只在 https 下注册。
请确认是通过 https 打开的页面；之后重新添加一次即可。

### 浏览器打开正常，主屏幕图标却停在“连接投屏服务”

这一屏是“连不上投屏服务器”的兜底页，**与手机是否连着校园 Wi-Fi 无关**，标题里的“连接”指的是连服务器。
Safari 里打开走实时网络所以正常；主屏幕图标是独立窗口（无地址栏、没有证书警告的“继续”入口），
用的是添加图标时固化的地址 + Service Worker 缓存，因此同一个链接会出现两种结果。

先看这一屏副标题给出的具体原因，它会写明是超时、连不上（多为 https 证书未被信任）、
还是“服务器返回 HTTP 4xx”（多半是图标指向了旧地址/旧域名，例如已不在服务端 Host 白名单里的域名），
下面一行还会显示失败请求的完整地址（可长按复制）。

处理办法，按顺序试：

1. 点这一屏的“清除缓存并重新打开”——它会清空 Cache Storage、注销 Service Worker 并重新加载。
   注意这一步要求当前网络能连上服务器，否则清完缓存后浏览器只会显示“无法打开页面”。
2. 仍不行就**长按图标删除**，用 Safari 打开 `https://10.30.13.1/myclass/ios/`（大屏弹窗第 2 步二维码），
   分享 → 添加到主屏幕，重新添加一次。**重加之前先在有网的状态下打开一次页面**，新的离线缓存才会装上。
3. 如果 Safari 每次打开都先弹“无法验证服务器身份”，说明自签证书没信任：按大屏弹窗第 1 步安装 1Panel-CA
   并在“证书信任设置”里打开“完全信任”。独立窗口不会给“继续访问”的机会，证书不信任时它必然连不上，
   只能靠 Service Worker 缓存把界面撑起来（看起来“能打开”，其实所有请求都失败了）。

### iPad 上演讲者视图按钮/备注跑到屏幕外

iPadOS Safari 里 `position:fixed` 元素的 `height:100%` 跟的是“布局视口”，会把页脚和备注推到 Safari 工具栏后面；同时 Safari 不会可靠地把 flex 容器高度传给 `<canvas>` 的 `max-height`，预览图会撑破面板、盖住页脚和“关闭”按钮，看起来像“关不掉”。现在演讲者视图按 `visualViewport` 精确铺满可视区域（键盘/工具栏变化时同步），预览画布绝对定位并裁在面板内。更新后 iPad 刷新一次页面即可。

### 课件预览加载失败（iOS 网页版 / 旧内核浏览器）

新版本 pdf.js（4.x / 5.x）的 worker 在独立线程里运行，需要浏览器**原生**支持 `Promise.withResolvers`
（Chrome 119+ / Safari 17.4+）。页面里的兜底补丁只在主线程生效、进不了 worker，旧内核（例如部分安卓
系统浏览器、iOS 15/16 的 Safari）会表现为 worker 反复加载、课件 PDF 一次都不请求，最后提示
“课件预览加载失败”。

现在 iOS 网页版会先检测浏览器是否原生支持：不支持时直接使用旧版 UMD 构建（与大屏端的判断一致）；
现代构建在运行期仍启动失败时，也会在整个会话内退回旧版构建再试一次。旧设备刷新一次页面即可恢复，
不需要重装浏览器。若页面仍是旧版，用更新提示里的“清除缓存并更新”。

- **上传与识别**：课件列表支持 `.html / .htm`（单文件，图片音频建议内联），也可在手机文件管理器里用“打开方式/分享”选 MyClass 导入。列表显示“网页”标记，手机端不执行网页脚本，只负责打开/关闭/刷新。
- **大屏显示**：大屏用**沙箱 iframe** 铺满舞台显示，默认触摸直接交给网页（可以直接点、拖、玩互动）；点大屏画笔/板擦后，透明标注层浮到网页上方，可在网页上圈画讲解，点“指针”又回到网页交互。笔迹记在独立页码上，不写进网页，也不和下面 PDF 课件的笔迹混在一起。
- **关闭恢复**：网页课件是覆盖层，不销毁下面的课件/摄像头/黑板。手机点“关闭”或大屏右上角“关闭”后，原课件按原页码、缩放和笔迹恢复。
- **独立窗口**：大屏右上角“新窗口打开”可以把网页放到独立浏览器窗口运行，适合少数在 iframe 里受限的互动课件；手机上的“新窗口”按钮会通知大屏打开（浏览器拦截弹窗时大屏会提示）。
- **安全**：上传的 HTML 即使直接被打开也带 `Content-Security-Policy: sandbox`，运行在不透明源里，拿不到课堂页面/管理页的本地存储和账号数据；网页不能使用 localStorage/IndexedDB、摄像头、麦克风等能力，纯 DOM/Canvas/WebGL 互动不受影响。
- **网络**：AI 生成的页面常用外网 CDN（Tailwind、Three.js 等）。只有校园内网的教室会加载失败，需要老师把资源内联后再上传；大屏打开时不会因为 CDN 失败而影响其他功能。

验证：`node --test server/coursewareHtml.test.js`（上传、列表 kind=html、响应沙箱头）；大屏覆盖层用浏览器验证打开/批注切换/关闭恢复/刷新/消息通道。

### 图片与课件笔记持久保存

大屏和手机在服务器图片、PDF（含转换后的 Office 课件）上所做的批注，会随文件 ID 保存到服务器的 `.annotations/` 目录。重新打开、重命名、关闭课堂、重启服务器后仍保留，图片为单页，课件按页恢复。主动“清空”只清当前页，撤销和板擦结果也会保存；删除文件时一并删除笔记。文件副本与其他账号的独立文件互不串用。黑板、实时摄像头及外部网页不属于文件笔记。

部署后大屏与 iOS 页面需刷新一次。存储采用按顺序追加并落盘的笔迹日志，服务器确认前不会将笔迹当作已保存；保存失败会提示。备份课件时须包含隐藏的 `.annotations/` 目录。尚未上线此功能前的历史课堂内存笔记无法追溯恢复。

验证：`node --test server/fileNotes.test.js`；配置 Playwright 后运行 `node web/file-notes.browser.cjs` 可验证实际大屏书写、图片重开、断线保留缩放、多页课件、iOS 恢复和清屏。

### PPTX 内嵌视频

PPTX 上传后会提取常见的内嵌视频（MP4、M4V、MOV、WebM 等），按幻灯片页码提供“本页视频”按钮。大屏可直接播放，iOS 与 Android（1.9.3 起）手机可远程打开、播放、暂停和前后跳转，返回课件后保留页码、缩放和笔记。已有 PPTX 会在首次请求视频信息时延迟提取。PowerPoint 外链视频、电脑本地路径和不兼容浏览器的视频编码不会被上传；建议使用 H.264/AAC 编码 MP4。删除课件会删除提取的视频附件。

版本：大屏 1.9.2、iOS 1.5.3（2026-10-15）。

### PPTX 演讲者备注与演讲者视图

PPTX 上传时，服务器直接从 `ppt/notesSlides/*` 提取每张幻灯片的演讲者备注（跳过页码、页脚、日期等占位符），不依赖 LibreOffice，也不改变转换后的 PDF。Android / iPhone / iPad 打开有备注的课件时，课件播放页会出现“演讲”按钮，点开即全屏“演讲者视图”：

- **当前页 / 下一页预览**：主界面已经渲染好的当前页直接缩放复用，其余页按预览分辨率渲染并缓存最近几页，翻页几乎即时；到最后一页时提示“已是最后一页”。
- **演讲备注**：显示本页备注，文字多时自动滚动；点“编辑”可当场修改并保存（编辑时临时收起预览，把空间让给输入框和键盘）。顶部 **A− / A+** 可调备注字号（四档，阅读与编辑同步，选择记忆在本机）。
- **本页视频**：当前幻灯片有 PPTX 内嵌视频时出现“本页视频”，在演讲者视图内选片并播放 / 暂停 / 前后 10 秒；视频仍在大屏播放（学生看得到），关闭面板后回到演讲者视图。
- **计时器**：首次打开自动开始，可暂停 / 继续 / 重置；同一课件关闭再打开继续累计，切换课件归零。
- **页码进度**：顶部显示“第 X / Y 页”，底边进度条随翻页前进；页脚“上一页 / 下一页”直接翻页并同步大屏。
- **横竖屏自适应**：横屏左侧当前页、右侧上下分“下一页 + 备注”；竖屏纵向排列。手机和平板都按可用宽高分配空间。

备注按“原幻灯片编号”保存：动画展开后同一张幻灯片的多个状态页共用一段备注。修改按“课件 ID + 教师账号”保存到课件目录的隐藏目录 `.notes/<课件ID>/<用户ID>.json`，只对本人生效；共享课件不会把一位老师的讲稿串给另一位老师，同一账号在 Android 与 iPad 上看到的是同一份备注。备注只在手持设备显示，大屏投影不显示；普通 PDF、链接课件和提取失败的文件不会出现该按钮。仅支持 `.pptx`（旧版 `.ppt` 需另存为 `.pptx` 后重新上传）；已有 PPTX 在首次请求备注时延迟提取并缓存；删除课件会同时删除其备注修改。

验证：`node --test server/pptxNotes.test.js server/coursewareNotes.test.js server/coursewareNotesHttp.test.js`；Android 端用 `dev.ps1 -GradleArgs '-PMYCLASS_SERVER_URL=http://10.0.2.2:3107/myclass'` 在模拟器里跑通横竖屏、查看/修改、字号、本页视频、计时与翻页；iOS 端用浏览器在手机/平板横竖屏四种尺寸下验证布局、预览耗时、备注滚动/保存、字号与本页视频面板。

### Android 课件预览恢复（1.9.2-2026101502）

手机 PDF 预览会自动删除无法打开的缓存并重新下载。网络或文件异常时保留翻页遥控，并提供“重新加载预览”；单个文件失败不再影响后续课件，返回菜单后继续播放也会重新尝试。页面重建后忽略旧视图的下载/渲染回调，避免旋转或快速切换时把结果显示到旧视图。可用隔离测试服务器与 `am instrument -w -e preview true cn.edu.nb3.myclass.test/cn.edu.nb3.myclass.ImportFlowInstrumentation` 验证恢复、翻页、HTTP 失败重试和切换文件。

大屏抽姓名控件在课件、黑板、视频模式分别跟随对应的底部工具栏，备用入口也固定在底部。网页更新无需重启服务；安卓修复需安装上述新版 APK，发布时先替换实际安装包，再更新 `appVersion`。

### Android 文件笔记与内嵌视频（1.9.3-2026101503）

Android 接收服务器的文件笔记快照，图片及 PDF 按文件/页码恢复，包括橡皮、荧光笔、虚线、点划线和直线。下载/渲染晚于笔记到达、翻页、界面重建及返回菜单不会清掉已恢复的笔记；只有主动清屏、撤销等编辑操作会同步修改服务器笔记。发出的笔迹携带文件 URL，避免迟到消息写入其他文件。

PDF 课件控制栏新增“本页视频”入口，同页多个视频可选择；动画展开页按原幻灯片映射查找视频。控制面板提供播放、暂停、前后 10 秒、返回课件，实际视频在大屏播放，不替换手机的 PDF 预览或其笔记。视频提取在后台独立进行，失败后可重试，不阻塞 PDF 预览。

验证：先用 `dev.ps1 -GradleArgs '-PMYCLASS_SERVER_URL=http://10.0.2.2:3107/myclass'` 增量安装调试包，再构建并安装 `:app:assembleDebugAndroidTest` 的测试 APK，配置 Playwright 后运行 `node scripts/test-android-notes-videos.cjs`。测试使用独立服务器、测试账号和实际 Android/浏览器信令，检查图片/PDF 持久笔记、横竖屏重建、清屏后的服务器结果、动画页视频入口及播放控制；通过项目 `ui.ps1` / `shot.ps1` 采集界面证据。

### Android 屏幕共享与电视笔迹（1.9.9-2026102404 / 大屏 1.0.4）

屏幕共享黑屏的根因是采集尺寸方向：旧代码固定按「长边 × 短边」创建虚拟显示，竖屏手机
（1080×2400）会得到一个 2400×1080 的横屏缓冲，与真实屏幕方向不一致，MediaProjection
镜像出来是黑屏；横屏平板 / 横屏手机碰巧正常，所以此前只在部分设备复现。
现在按整块屏幕的真实宽高比缩放并保持方向（1080×2400 → 864×1920），同时用
`WindowManager.maximumWindowMetrics` 而不是 App 窗口的 `resources.displayMetrics`，
避免标题栏 / 导航栏 / 刘海造成宽高比不一致。摄像头和屏幕共享都强制优先 VP8，
屏幕共享长边限制 1920、最高 8 Mbps，兼顾老电视解码。

屏幕共享开始后 App 自动退到后台，避免大屏一直显示 App 自己的深色共享页；系统通知保留，
点通知可回到控制页停止共享。

电视端 1.0.4 补上笔迹渲染适配：有压感时使用 perfect-freehand 轮廓；手指 / 普通电容笔
整笔压力恒定时按**归一化书写速度**计算线宽（InkSpeed），与电视分辨率无关，不会因为
电视更宽就被算成一条细线；荧光笔、虚线、点划线、直线工具和板擦与大屏一致。线宽按电视
密度换算，不随课件缩放变化。电视端 answer 现在只保留 VP8：摄像头原本就强制 VP8，
屏幕共享在旧版手机端没有强制，若协商到 H.264，部分老电视 1080p 以上解码失败就是黑屏。
只保留 VP8 后，即使手机端不更新也必须用 VP8 发送。

同时修正 `SurfaceViewRenderer` 使用 `MATCH_PARENT` 导致竖屏投屏和 4:3 摄像头画面被横向
拉伸的问题，改为 `WRAP_CONTENT` 居中，按视频原始比例显示并保留黑边；收到视频 offer 后
先显示等待提示，10 秒无首帧会提示检查发送端网络，不再只显示无提示黑屏。

网页大屏的摄像头横竖屏以解码后的 `videoWidth/videoHeight` 为准（`app.js` 的
`updateVideoPresentation`），个别浏览器对 WebRTC 旋转元数据的处理与手机上报不一致时，
不会再按 landscape 的 cover 规则把竖屏画面裁掉；屏幕共享仍按手机上报的采集方向处理。

关于手机端：电视“黑屏”的主要差异是编解码协商，**只更新电视端就能覆盖**（电视端现在强制
VP8）。但“共享过程中旋转手机只剩一个小横屏”是手机虚拟显示尺寸的问题，**必须更新手机端
1.9.9-2026102404**：新增 DisplayListener，旋转后调用 `changeCaptureFormat` 把虚拟显示
resize 成新的整屏方向。手机 2404 还包含竖屏采集尺寸修正、屏幕共享长边 1920 / 8 Mbps
降低老电视解码压力、共享后自动退后台。摄像头链路本次没有改动（仍是 1280×960、VP8），
网页端回归测试通过：摄像头 768×1024、屏幕共享 1920×1200 均能正常显示。

模拟器验证：竖屏 1600×2560 下屏幕共享输出 1200×1920（日志
`Screen capture display=1600x2560 virtualDisplay=1200x1920`），浏览器大屏收到
1200×1920 竖屏画面；共享中切到横屏 2560×1600 后日志出现
`Screen capture resized to 1920x1200`，浏览器大屏同步变成 1920×1200，
`state.videoOrientation` 从 portrait/0 变为 landscape/90，不再出现“小横屏”。
电视端收到 1200×1920 流后按比例居中显示、两侧黑边，合成发送端
收到的 answer 只有 `a=rtpmap:96 VP8/90000`；只发 offer 不产生帧时，电视 4 秒显示
“正在接收视频画面…”，10 秒后提示“尚未收到视频画面…”，不再停在无提示黑屏。
压感笔迹、速度渐变笔迹、荧光笔、虚线、直线、板擦及上述等待提示截图见
`android/AndroidStudioProject/tv/build/evidence/ink-1.0.4/`。

### PPTX 演讲者备注与演讲者视图（Android 1.10.9 / iOS 1.6.4）

PPTX 的演讲者备注随课件一起提取，Android 与 iPhone / iPad 网页版在播放有备注的课件时显示“演讲”按钮：点开是全屏演讲者视图，同时显示**当前页**、**下一页预览**、**本页演讲备注**、**计时器**与**页码进度**。备注可就地修改并保存，保存后立即生效，下次打开或换设备（同一账号）仍然有效；文字多时备注区可滚动；横屏为“左当前页 / 右下一页+备注”，竖屏为纵向排列，手机与平板都按可用空间铺满。

演讲者视图还支持：**A− / A+ 调节备注字号**（四档、阅读与编辑同步、记忆在本机）；当前幻灯片有 PPTX 内嵌视频时出现**“本页视频”**，可直接选片并播放 / 暂停 / 前后跳转（视频仍在大屏播放，学生看得到）。预览加载优先复用主界面已渲染的当前页并缓存最近几页，打开演讲者视图时当前页预览基本即时出现。

备注按幻灯片编号对应，动画展开的多页共用一段；没有备注的页可以现场添加；共享课件中每位老师保存的是自己那份修改（`.notes/<课件ID>/<用户ID>.json`）。备注不投到大屏，普通 PDF 与链接课件不显示按钮。

已有 PPTX 会在首次打开备注时延迟提取；删除课件会一并删除备注修改。备份课件目录时需包含隐藏的 `.notes` 与 `.annotations`。验证：`node --test server/pptxNotes.test.js server/coursewareNotes.test.js server/coursewareNotesHttp.test.js`；Android 端在模拟器上跑通横竖屏、查看/修改、字号、本页视频、计时与翻页，iOS 端用浏览器在手机/平板横竖屏四种尺寸下验证布局、预览耗时、备注滚动/保存、字号与本页视频面板。
