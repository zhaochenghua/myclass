# iOS 课件交互与 Android 对齐

- iOS 页面跟随系统横竖屏。Safari/PWA 不允许普通网页可靠地锁定设备方向，页面内旋转补偿也不能改变系统方向，因此没有提供锁定方向按钮。
- 列表缩略图为 96×72（4:3），完整容纳页面；网页与链接使用独立占位缩略图。点击缩略图进入独立连续文档预览；点击课件标题沿用播放入口。长文件名最多显示两行并自动省略，横屏双列卡片按行对齐。
- 连续预览按原始幻灯片显示每页最后一个动画状态，跳过隐藏页。只渲染可见页，顺序执行，离屏画布缓存上限 24 MB；预览不发送课堂消息。
- 快速翻页取代页码输入框：拖动滑块预览最终动画状态，松手跳到所选原始页的第一个状态，取消不改变大屏。
- 竖屏播放使用固定工具区与可收缩舞台，短屏下工具区可滚动，避免 A4 课件挤出底部按钮。
- 标注的「清空」按钮常驻在底部（抽学生 / 班级设置 之后），手势模式与画笔模式都可见可用，无笔迹时置灰；画笔工具条只留颜色、板擦、撤销，与 Android 一致。
- Android、大屏和服务器通信逻辑不变，没有新增消息或字段。共享页码模块仅增加分组辅助函数；链接模块的几何获取参数保留原有默认行为。
- 课件 PDF 渲染优先使用新版 pdf.js ESM 构建；浏览器没有原生 `Promise.withResolvers`（Chrome < 119 / Safari < 17.4）时直接使用旧版 UMD 构建——新版 worker 在独立线程里运行，页面内的兜底补丁传不进去，旧内核会 worker 启动失败且一次都不请求 PDF，界面只有“课件预览加载失败”。现代构建运行期失败时会整体退回旧版并重试一次。加载器逻辑在 `web/ios/js/pdfview.js`。

## 验证

```powershell
node scripts/test-ios-reader.cjs
$env:MYCLASS_WEBKIT='1'
node scripts/test-ios-reader.cjs
```

测试使用 Playwright、隔离服务器和测试数据，覆盖 390×844、375×568、768×1024、844×390、1180×820。检查 4:3 比例、网页/链接占位缩略图、长文件名两行排布、连续预览最终状态、原始页映射、快速翻页的预览与提交、取消、独立预览不发送信令、A4 控件边界及笔迹坐标。截图在系统临时目录 `myclass-ios-reader-proof`。

Windows WebKit 不提供 WebRTC，WebKit 测试中的大屏由 Edge 运行，iOS 页面由 WebKit 运行。浏览器自动化不能替代真机 Safari/PWA 对系统旋转、安全区、Apple Pencil 和原生滑块触摸的验证。
